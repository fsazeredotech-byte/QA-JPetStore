# 🐞 BUG-003 — Campos de senha do cadastro mostram a senha em texto visível

| Campo | Descrição |
|---|---|
| **ID** | BUG-003 |
| **Título** | Os campos "New password" e "Repeat password" do cadastro exibem a senha em texto claro |
| **Ambiente** | https://jpetstore.mate.academy · navegador baseado em Chromium · 03/11/2026 |
| **Caso de teste relacionado** | Encontrado durante o PS-TC-002 (teste exploratório) |
| **Pré-condição** | Usuário não logado. |
| **Passos para reproduzir** | 1. Abrir https://jpetstore.mate.academy/actions/Catalog.action<br>2. Clicar em **Sign In** → **Register Now!**<br>3. Digitar qualquer valor em **New password** e **Repeat password** |
| **Resultado esperado** | Os caracteres digitados aparecem mascarados (•••). |
| **Resultado atual** | A senha aparece legível na tela. Inspecionando a página, os dois campos são `<input type="text">` em vez de `<input type="password">`. |
| **Severidade** | 🟡 **Minor**: não quebra o fluxo, mas expõe a senha a quem estiver olhando a tela (*shoulder surfing*), e o navegador pode guardá-la no autocompletar como texto comum. |
| **Prioridade** | 🟠 **Alta**: risco de segurança com correção simples (trocar o `type` do campo). |
| **Evidência** | [`evidencias/BUG-003-senha-visivel.jpg`](../evidencias/BUG-003-senha-visivel.jpg) (a senha foi borrada na imagem publicada) |
| **Reportado por** | Fabricio S Azeredo · 03/11/2026 |

## 🔐 Observação de segurança
Um campo de senha deve usar `type="password"`. Assim, o valor fica mascarado na tela e os navegadores e gerenciadores de senha tratam o dado como sensível.

💡 Exemplo de **severidade menor com prioridade alta**: o impacto técnico é pequeno, mas a correção é rápida e o risco de segurança justifica corrigir logo.
