# 🐞 BUG-001 — Cadastro com User ID já existente mostra erro 500 com detalhes técnicos, em vez de mensagem amigável

| Campo | Descrição |
|---|---|
| **ID** | BUG-001 |
| **Título** | Cadastro com User ID já existente retorna "HTTP Status 500 – Internal Server Error" com stack trace e SQL expostos |
| **Ambiente** | https://jpetstore.mate.academy · navegador baseado em Chromium · 03/11/2026 |
| **Caso de teste relacionado** | [PS-TC-001](../casos-de-teste/casos-de-teste-cadastro.md#ps-tc-001--não-aceita-um-user-id-já-existente) → PS-REQ-001 |
| **Pré-condição** | Existe a conta `QAFab0311261210`, criada no PS-TC-003. Usuário não logado. |
| **Passos para reproduzir** | 1. Abrir https://jpetstore.mate.academy/actions/Catalog.action<br>2. Clicar em **Sign In** → **Register Now!**<br>3. Em **User ID**, digitar `QAFab0311261210` (um ID que já existe)<br>4. Preencher os demais campos com dados válidos<br>5. Clicar em **Save Account Information** |
| **Resultado esperado** | O formulário continua aberto e mostra uma mensagem de erro amigável informando que o User ID já existe e deve ser único (PS-REQ-001). |
| **Resultado atual** | A página **"HTTP Status 500 – Internal Server Error"** é exibida. Ela mostra para o usuário final:<br>• o stack trace completo (classes Java, Stripes, Spring, MyBatis);<br>• o comando SQL `INSERT INTO ACCOUNT (...)`;<br>• os nomes da tabela `ACCOUNT` e da chave `PK_ACCOUNT`, e o arquivo `AccountMapper.xml`.<br>A conta duplicada **não** é criada (o banco recusou com `DuplicateKeyException`), e a conta original continua intacta (login e dados conferidos depois do erro), mas o usuário não recebe nenhuma orientação e perde os dados digitados no formulário. |
| **Severidade** | 🟠 **Major**: a regra de unicidade é protegida pelo banco, mas o fluxo de erro está quebrado e expõe informações internas do sistema. |
| **Prioridade** | 🟠 **Alta**: é o caminho comum de quem tenta um ID que já está em uso. |
| **Evidência** | [`evidencias/BUG-001-erro-500.jpg`](../evidencias/BUG-001-erro-500.jpg) |

## 🔁 Reprodução
O erro foi **reproduzido manualmente** pelo testador, digitando todos os campos, ao repetir um User ID já cadastrado. O comportamento não depende de automação.

## 🔐 Observação de segurança
Mostrar stack trace e SQL para o usuário é uma **exposição de informações** (*information disclosure*). Ela revela tecnologias, bibliotecas, nomes de tabelas e a estrutura de consultas, e isso pode ajudar um atacante. O recomendado é tratar a exceção, exibir uma mensagem genérica e registrar os detalhes apenas no log do servidor.

## 💡 Sugestão
Antes de inserir a conta, verificar se o User ID já existe (ou tratar o `DuplicateKeyException`) e voltar ao formulário com a mensagem: *"Este User ID já está em uso. Escolha outro."*
