# 🐞 BUG-004 — Cadastro com User ID vazio ou só com espaços é recusado sem nenhuma mensagem de erro

| Campo | Descrição |
|---|---|
| **ID** | BUG-004 |
| **Status** | 🔴 Aberto — observado em 03/11/2026 |
| **Título** | Ao salvar o cadastro com User ID vazio ou só com espaços, o formulário volta sem mensagem explicando o erro |
| **Ambiente** | A01: navegador integrado do app Claude Desktop 4.4212.0 (Chromium 152.0.7977.167) · Windows 10 64-bit · https://jpetstore.mate.academy |
| **Caso de teste relacionado** | [PS-TC-004](../casos-de-teste/casos-de-teste-cadastro.md#ps-tc-004--não-aceita-user-id-vazio-premissa-q-01) → premissa Q-01 (User ID obrigatório) · [PS-TC-005](../casos-de-teste/casos-de-teste-cadastro.md#ps-tc-005--não-aceita-espaços-premissa-q-04), variação 005-d (só espaços) |
| **Pré-condição** | Usuário não logado. |
| **Passos para reproduzir** | 1. Abrir https://jpetstore.mate.academy/actions/Catalog.action<br>2. Clicar em **Sign In** → **Register Now!**<br>3. Deixar **User ID** vazio<br>4. Preencher a senha e os demais campos com dados válidos<br>5. Clicar em **Save Account Information** |
| **Resultado esperado** | O cadastro não é concluído **e** uma mensagem visível informa que o User ID é obrigatório. |
| **Resultado atual** | O formulário é exibido novamente com os dados preenchidos e o cadastro não é concluído na interface. **Nenhuma mensagem de erro aparece na tela.** No código da página, o campo User ID recebe `class="error"` e o foco, mas sem nenhum destaque ou texto visível. |
| **Frequência** | Observado em **2/2** tentativas: User ID vazio (PS-TC-004, 14:38) e User ID com 28 espaços (PS-TC-005-d, 15:37), ambas no ambiente A01. |
| **Severidade** | 🟡 **Minor**: a regra é aplicada, mas o usuário não entende por que o cadastro não foi concluído. |
| **Prioridade** | 🟡 **Média**: afeta a usabilidade do cadastro; o cadastro não foi confirmado na interface (estado do banco não verificado). |
| **Evidência** | [01 antes de salvar](../evidencias/PS-TC-004_20261103_143800_T01_01-antes-salvar.jpg) · [02 depois de salvar](../evidencias/PS-TC-004_20261103_143800_T01_02-depois-salvar.jpg) · **005-d:** [01](../evidencias/PS-TC-005d_20261103_153631_T01_01-antes-salvar.jpg) · [02](../evidencias/PS-TC-005d_20261103_153631_T01_02-depois-salvar.jpg) (o campo aparece selecionado em cinza, único sinal visual) |
| **Limitação** | Os prints 01 e 02 são visualmente quase iguais: essa é justamente a falha (nenhuma mudança visível). A marcação `class="error"` foi observada no código da página e não aparece nos prints. Não foi verificado se alguma conta com ID vazio foi criada no banco. |
| **Execução** | **Testador:** digitou a senha, First name, Last name e um e-mail. **Claude** (a pedido do testador): trocou o e-mail para `teste.qa@example.com`, digitou Phone, Address 1, City, State, Zip e Country, conferiu no código da página que o User ID estava vazio, capturou os prints e clicou em Save. |
