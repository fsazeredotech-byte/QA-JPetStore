# 🐞 BUG-002 — Cadastro aceita User ID com caractere especial ("!")

| Campo | Descrição |
|---|---|
| **ID** | BUG-002 |
| **Título** | O campo User ID aceita caractere especial, e a conta `User!123` é criada |
| **Ambiente** | https://jpetstore.mate.academy · navegador baseado em Chromium · 03/11/2026 |
| **Caso de teste relacionado** | [PS-TC-002](../casos-de-teste/casos-de-teste-cadastro.md#ps-tc-002--não-aceita-caracteres-especiais), variação 002-a → PS-REQ-002 |
| **Pré-condição** | Usuário não logado. O User ID `User!123` ainda não existe. |
| **Passos para reproduzir** | 1. Abrir https://jpetstore.mate.academy/actions/Catalog.action<br>2. Clicar em **Sign In** → **Register Now!**<br>3. Em **User ID**, digitar `User!123`<br>4. Preencher a senha e os demais campos com dados válidos<br>5. Clicar em **Save Account Information**<br>6. Clicar em **Sign In** e entrar com `User!123` e a senha definida |
| **Resultado esperado** | No passo 5, uma mensagem de erro informa que o User ID deve conter apenas letras e números (PS-REQ-002), e a conta não é criada. |
| **Resultado atual** | No passo 5, nenhuma mensagem de erro aparece e o sistema volta à página principal. No passo 6, o login funciona ("Welcome Teste!"), e a página **My Account** mostra **User ID: User!123**. A conta foi criada e salva com o caractere especial. |
| **Severidade** | 🟠 **Major**: viola diretamente uma regra do requisito e permite dados inválidos no banco. |
| **Prioridade** | 🟠 **Alta**: afeta todo novo cadastro. |
| **Evidência** | [`evidencias/BUG-002-conta-criada.jpg`](../evidencias/BUG-002-conta-criada.jpg) (página My Account mostrando o User ID `User!123`) |
| **Reportado por** | Fabricio S Azeredo · 03/11/2026 |

## 🔁 Reprodução e padrão observado (03/11/2026)

| User ID | Tem símbolo? | Login automático após salvar? | Login manual depois? | Como foi digitado |
|---|---|---|---|---|
| `QAFab0311261210` (controle) | ❌ não | ✅ sim ("Welcome teste1!") | ✅ funcionou | 100% manual |
| `User!123` | ✅ `!` | ❌ não | ✅ funcionou | campos extras por script; ID e senha manuais |
| `User@123` | ✅ `@` | ❌ não | ✅ funcionou | campos extras digitados pelo Claude; ID e senha manuais |

**Padrão:** com caractere especial, a conta é **salva** (o login manual funciona e uma nova tentativa com o mesmo ID gera o erro 500 de duplicidade do [BUG-001](BUG-001.md)), mas o sistema **não faz o login automático** depois do cadastro, ao contrário do ID sem símbolo. O ID inválido passa pela validação e causa um comportamento inconsistente no fluxo seguinte.

## 📝 Observações
- Na primeira execução, os campos (exceto a senha) foram preenchidos por script. A validação do User ID acontece no **servidor**, e o login manual feito depois confirmou que a conta existe. A variação 002-b (`User@123`) confirmou o mesmo comportamento; a 002-c (`User#123`) ainda será executada.
- A causa da falta de login automático não pode ser confirmada em teste caixa-preta; fica como ponto para o time de desenvolvimento investigar.
