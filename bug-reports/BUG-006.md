# 🐞 BUG-006 — User ID com 50 caracteres causa erro 500 ("string data, right truncation") em vez de validação de tamanho

| Campo | Descrição |
|---|---|
| **ID** | BUG-006 |
| **Status** | 🔴 Aberto — observado em 03/11/2026 |
| **Título** | Cadastro com User ID longo (50 caracteres) exibe "HTTP Status 500" com SQL e nomes de tabela expostos |
| **Ambiente** | A01: navegador integrado do app Claude Desktop 4.4212.0 (Chromium 152.0.7977.167) · Windows 10 64-bit · https://jpetstore.mate.academy |
| **Caso de teste relacionado** | [PS-TC-E01](../casos-de-teste/casos-de-teste-cadastro.md#ps-tc-e01--user-id-muito-longo-dúvida-q-05) (exploratório) · dúvida Q-05 |
| **Pré-condição** | Usuário não logado. |
| **Passos para reproduzir** | 1. Abrir https://jpetstore.mate.academy/actions/Account.action?newAccountForm=<br>2. Preencher a senha e os demais campos com dados válidos<br>4. Clicar em **Save Account Information** |

O campo User ID **não tem `maxlength`** no código da página. |

Signon failed."). ⚠️ Isso **não prova** que nenhum registro foi gravado (por exemplo, na tabela ACCOUNT); só mostra que não é possível entrar com essa conta. |

## 🔐 Observação de segurança
Assim como no BUG-001, a página de erro revela a estrutura do banco (tabela `SIGNON`, coluna `USERNAME`) e o SQL usado. Um atacante pode usar isso para planejar ataques.

## 💡 Sugestão
Validar o tamanho do User ID no servidor antes de gravar (e adicionar `maxlength` no campo), mostrando uma mensagem amigável.
